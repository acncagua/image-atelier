# ローカルSwinIRアップスケーラー

実装・検証日: 2026-09-12。画像処理にはPC内のSwinIRだけを使い、今回の外部画像API呼び出し・モデルのダウンロードは0回。PyTorch等のパッケージ取得はセットアップ時に実施した。

## このPCでは設定済み

Image Atelierを起動し、モードの「アップスケール」を選ぶ。初期値は2倍、タイル192、重なり8。1920×1088は3840×2176になる。元画像を上書きせず、結果は生成と共通の「履歴・ジョブ」に登録される。

今回のモデルは、提示されたReForge側のファイルを、アプリ専用のgit対象外フォルダー `models/SwinIR_4x.pth` にコピーした。元モデルは変更していない。機器設定は `data/upscale-settings.json` に保存し、APIキー設定とは分離する。設定ファイルがない場合は、アプリ内の `.venv-swinir/Scripts/python.exe` と `models/SwinIR_4x.pth` を初期パスに使う。

「詳細・環境設定」ではPython・モデルの絶対パスを変更し、「GPU・モデルを診断」で実モデルの小さなFP32推論を試せる。診断もローカルGPUキューで処理する。CUDAなし、未設定、不正モデルは失敗として表示し、CPUへ自動で切り替えない。これらが未設定でも既存のAPI編集機能は起動する。

## 別PCでの導入

Windows、Python 3.12、対応NVIDIAドライバーが必要。Image Atelierフォルダーで次を実行する。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup-swinir.ps1 -ModelPath "D:\Models\SwinIR_4x.pth"
```

モデルは自分でローカルへ配置する。このスクリプトはモデルをダウンロードしない。`-ModelPath` を省略した場合は画面から設定する。通常の起動は従来どおり `start.cmd`。

専用環境は `.venv-swinir`。ReForgeの仮想環境やパッケージは変更しない。セットアップスクリプトはCUDA 12.8版PyTorchを先に導入し、`requirements-swinir.txt` の固定バージョンを満たす。セットアップ完了後の推論はネットワークを使用しない。推論子プロセスではPythonソケットの接続も拒否する。

## 指定方式と上限

- 倍率は1倍超〜4倍。最終寸法は `floor(入力寸法×倍率+0.5)`。
- 解像度は正の整数で、少なくとも片方が入力より大きいこと。両辺とも入力の4倍以下。
- 入力は各辺2048px以下、総画素2,097,152以下。
- 出力・4倍中間画像は各辺8192px以下、総画素33,554,432以下。
- タイルは32〜512px、8の倍数。重なりは0以上・タイル未満。4096タイルを超える指定は拒否。

上限は `upscale_limits.json` に集約し、UIとサーバーで共用する。2048×1024→8192×4096の実GPU試験まで実施した。最大タイル512は512×512入力で確認した。すべての寸法・タイル・重なりの組み合わせを保証するものではない。

SwinIRは毎回ネイティブ4倍で1回推論する。2倍・1.5倍では4倍結果をLanczosで縮小する。4倍では縮小しない。解像度指定で比率が違う場合は、透明余白追加・中央切り抜き・変形から明示的に選ぶ。端数の余白・切り抜きは中央を基準とし、1px余る場合は右・下側へ配分する。

## 透過・色・メモリ

RGBを0〜1のFP32としてモデルへ渡し、RGB/BGR変換は挟まない。RGBAはアルファを分離し、完全透明画素のRGBを近傍の可視色で埋めてから推論する。アルファは通常補間し、縮小はpremultiplied alphaで処理する。不透明画像は推論出力でも不透明のRGBを維持する。アプリへの登録時は既存の作業用RGBA形式になるが、不要な透明画素は作らない。

ICCが入力にある場合だけ引き継ぐ。ICCなしの透過試験画像には、出力でもICCを付けなかった。モデルパスや機器設定はPNGメタデータへ埋め込まない。

タイルをwindowの倍数へ一時パディングし、推論後に取り除く。4倍画像と重みの配列はCPU上で保持し、GPUには1タイルずつ転送する。重なりは平均して合成する。最大入力でのCPU配列等の概算は約1.63GiBに実行環境分を加えた量。GPUをReForgeなどと同時使用した場合の空き容量をアプリが保証することはない。OOMは小さいタイルを案内して失敗にし、自動で再推論しない。

## ジョブ・取消・保存

APIジョブとは別のJSON記録と単一GPUキューを使う。保存先は `data/upscale-jobs/<UUID>/`。モデル識別・ハッシュ、入力ID、固定した要求、実出力、環境、精度、時間、タイル、幾何処理を記録する。APIの利用額・予約額・送信キューへは加算しない。

1回の登録操作はIndexedDBに保存した同じIDで再確認できる。新しく実行する操作は新IDを使う。待機取消と開始は共有ロックで確定する。実行中取消は「取消要求中」とし、現在のモデル読込・タイル処理が終わり、子プロセスが終了してから「取消」にする。保存確定が先に成立した場合は、取消成功とは返さない。

専用子プロセスは1ジョブごとに終了し、モデルを常駐させない。通常終了・取消で子プロセスの終了を待つ。異常時は取消ファイルで終了を求め、それでも止まらなければ自分が起動したWindowsプロセスツリーだけを終了する。ReForgeのプロセスを終了する処理はない。

サーバーの強制終了等で未完了になった記録は、次回起動時に「中断」とする。自動再推論しない。推論結果が保存済みなら「保存を再試行」で画像登録・書き出しだけを再開できる。原画像と既存成果物は上書きしない。

Windowsでの最初のアプリ経由試験ではPermissionErrorが発生した。状態ファイルの一時的な共有競合を想定し、同じ確定前ファイルの置換を短時間・最大20回だけ再試行し、変化のない進行情報は書き直さないようにした。これはファイル操作の再試行であり、SwinIRやAPIの再実行ではない。対策後のアプリ経由処理は成功した。最初の失敗記録は保持している。

## 障害復旧3件の修正（2026-09-12）

- 登録内容を `upscale-jobs/registrations/<id>.json` に先に永続保存する。`job.json` の保存失敗後も、同じID・入力なら登録を完了できる。入力変更は拒否し、正常な既存ジョブは変更しない。旧版の空フォルダーも再利用できるが、実行済みの可能性があるファイルが残る場合は保護する。
- `completed` の書込み失敗でも、子プロセスツリーの終了を確認してからPNGの形式・寸法・完全な読込みを検証し、画像登録と書き出しだけを再試行できる。`saving`、壊れた状態ファイル、状態ファイル欠損からの回収を含む。取消の記録・取消ファイルがある結果、壊れた画像、寸法不一致、処理中の結果は回収しない。環境情報が欠ける場合はモデル検証済みと表示しない。
- Windows 10以降では、非継承の専用Job Objectを作り、`PROC_THREAD_ATTRIBUTE_JOB_LIST` によって子プロセスを作成時から所属させる。`KILL_ON_JOB_CLOSE` により、サーバーの強制終了時にvenvランチャーを含む子孫を終了する。再起動時も同じジョブの残存ツリーの終了を確認してからキューを再開する。保存PIDを根拠に終了させる処理は使わない。旧版の管理外PIDが生存中または終了確認不能なら、無関係なプロセスを停止せず起動を保留する。

Windows実機で検証専用Uvicornだけを強制終了し、推論役のPythonとvenv子プロセスの両方が終了すること、無関係なPythonが生存すること、新しいUvicornを起動して旧ジョブを中断扱いにし、新規ジョブを完了できることを確認した。さらに子プロセス起動後・PID保存前に強制終了するケースも確認した。推論はモックで、CUDA処理ではない。

回帰結果: Python 86件（今回追加9件を含む）、配列4件、JavaScript 20件、合計110件成功。実GPU推論・物理的な電源断・ブラウザー操作は今回再検証していない。既存のRTX 5090測定は前回の記録。本番サーバーは停止したまま。
