# Image Atelier

Windowsで使う、OpenAI画像API専用のローカル編集UIです。元画像と役割付き資料を読み込み、指示文を確認して編集し、結果を比較・保存します。初期設定はモックです。実APIで新規生成・資料付き編集・マスク編集を確認済みです。試験の費用と結果不明の1件については [実API検証記録](docs/LIVE_TEST_RESULTS.md) を参照してください。

最初は「起動」と「モックで試す」を読んでください。API設定や部分修正の説明は、使うときに参照できます。

## 起動は start.cmd から

このPCでは導入とビルドが済んでいます。`start.cmd` をダブルクリックし、ブラウザーで [Image Atelier](http://127.0.0.1:18791) を開いてください。既に起動中ならURLを開くだけで使えます。

終了するには、起動したターミナルで **Ctrl+C** を押します。再起動は再び `start.cmd` を実行します。ブラウザーを閉じてもAPI処理や課金は取り消されません。処理中にサーバーを終了した場合、次の起動時には「結果不明」とし、自動再送しません。待機中だったジョブは「待機取消」になります。

別PCへの導入や環境の作り直しには、Python 3.12とNode.js 22.12以降が必要です。このフォルダーでPowerShellを開き、次を実行します。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1
.\start.cmd
```

`setup.ps1` は専用の `.venv` と `node_modules` に依存関係を導入し、画面をビルドします。SDのPython環境は変更しません。初回導入にはインターネット接続が必要ですが、モックの通常操作は外部通信しません。

## モックで一連の操作を試す

1. 「編集対象」に元画像を選択またはドロップします。
2. 顔資料があれば「参照資料」に追加します。なくても実行できます。
3. 「変更すること」「維持すること」を入力します。
4. モデル・品質・幅・高さ・形式・枚数（1〜4枚）を選び、「指示文を確認・編集」を開きます。
5. 画像の順序と役割を確認し、「この指示文で実行」を押します。
6. 完了後、左右の画像を比較します。「PNGを保存」で設定フォルダーへ保存し、「PNGダウンロード」でブラウザーから回収できます。

モック編集は元画像のコピーです。新規生成では文字入りの検査用パターンを返します。画像生成モデルによる改善や顔の維持を評価するための画像ではありません。

「次の編集対象にする」で結果から編集を続けられます。資料と変更・維持指示を引き継ぎます。「履歴・ジョブ」の「条件を復元」では当時の入力、マスク、手編集した送信指示文を読み込みます。同じ条件でも同一画像の再現は保証されません。

## 顔資料と塗りの資料を使い分ける

資料の役割は「顔資料」「全身資料」「色・質感資料」「衣装・小物資料」から選べます。顔資料には輪郭・目・鼻・口の比率を参照する指示を付け、肌の塗りと光は編集対象に合わせるよう指定します。複数人物を含む場合は「対象人物の説明」に識別の手掛かりを記入してください。

「顔を切り出す」を押し、元画像上を矩形にドラッグすると、その範囲を顔資料に追加します。顔検出AIは使用しません。顔の拡大比較は「100%」「拡大」で倍率を上げ、画像をドラッグして顔を表示します。左右の倍率と移動量は連動します。

キャラクターごとの資料と維持指示は、左側のプリセット欄で名前を付けて保存できます。同名のプリセットは更新されます。

## 部分修正では変更範囲を塗る

モードを「部分修正」にし、「ブラシ」で範囲を塗ります。「消しゴム」、ブラシ径、取り消し・やり直し、全消去に対応しています。「移動」で画像をドラッグし、ホイールまたは倍率ボタンで拡大します。

APIには編集対象を最初に送り、その画像と同寸法のマスクを付けます。画面で塗った場所は、送信マスクでは透明になります。APIによるマスク編集は、選択外の画素が必ず維持される仕組みではありません。

「変更範囲だけ合成」を選ぶと、API出力を元画像の選択範囲に合成した別画像を保存します。境界のぼかしは選択範囲の内側に適用します。塗っていない画素は作業用元画像と一致し、境界内の画素は変化します。結果と元画像の寸法が違う場合、合成を中止して理由を表示します。APIが内容の位置を動かしていないかは、比較画面で確認してください。

## 寸法を変える場合は方法を指定する

標準は1920×1088です。厳密な16:9のプリセットは2048×1152として区別しています。幅・高さ入力、縦横交換、16px単位の比率保持、元画像の実寸取得が使えます。未対応寸法は送信前に拒否し、候補を表示します。

結果の寸法が要求と違う場合は明示します。「寸法を明示的に調整」で中央切り抜き、透明余白追加、リサイズを選ぶと、上部の幅・高さに合わせて別画像を作ります。自動での変形や切り抜きは行いません。

入力の原ファイルはそのまま保持します。作業用PNGはEXIFの向きを反映し、ICCがあればsRGBに変換します。ICCがない画像はsRGBとして扱います。プレビューと合成はこの作業用画像を使います。CMYKや特殊プロファイルの完全な色再現は検証していません。

## 実APIのキーと料金管理を設定する

Flareの新規生成とSunburstの編集・マスクをPNG1枚で確認しています。顔の同一性や塗りの一致は保証しません。JPEG/WebPと複数枚はモックで検証しており、有料試験では未検証です。

実APIを使う場合は、[APIキー管理](https://platform.openai.com/api-keys)でキーを作成し、アプリ直下の `config.local.json` の空欄に保存します。

```json
{
  "openai_api_key": "ここにAPIキーを入力"
}
```

ファイルはUTF-8で保存してください。このファイルはGit対象外で、バックエンドだけが読み込みます。キーを画面、履歴、ログには返しません。ファイルのキーを優先し、空欄またはファイルがない場合は従来の環境変数 `OPENAI_API_KEY` を使います。キー変更後は画面を再読み込みしてください。今回のコード変更を反映する初回だけ、サーバーの再起動が必要です。

キーはファイルに平文で保存されます。このフォルダーはOneDrive配下なので、同期対象にしない場合はアプリをOneDrive外へ配置してください。キーをチャットや画面のプロンプトに貼らないでください。

画面の「設定」で接続方式をOpenAI APIにし、実API送信を有効にします。通常の実行では有料送信の確認ダイアログを出しません。結果不明の履歴から新規実行する場合だけ、追加課金の確認を表示します。キーがあるだけでは送信しません。

料金管理の標準は「通知のみ」です。旧設定も通知のみへ移行し、仮の予約額を理由に生成を止めません。「制限なし」「通知のみ」「上限で停止」を選択できます。通知・停止の期間は今日・今月・累計（登録日基準、日本時間）、金額はUSDです。通知額0は通知なしです。停止モードだけ1枚の仮計上額を詳細設定で指定します。未精算の待機・処理中・料金不明分は過去期間分も停止判定に含め、概算が得られたら概算へ置き換えます。実料金が仮計上額を超える場合があり、請求上限の保証ではありません。

今日・今月・累計の利用額は取得済み使用量からの概算で、料金不明件数を別表示します。実行前は同じモード・モデル・品質・寸法の直近最大10件から1枚あたりの平均を取り、今回の枚数を掛けた予想額を表示します。該当履歴がなければ不明と表示します。参照画像・指示文による差があるため確定額ではありません。モック・ローカルGPU処理はAPI料金集計から除外します。

Atelierの集計はOpenAIの実残高・アカウント全体の請求額ではありません。[公式の残高画面](https://platform.openai.com/settings/organization/billing/overview)と[公式Usage](https://platform.openai.com/usage)を確認してください。OpenAI側の残高不足・利用枠エラーと、Atelierで選択した停止上限は別のメッセージで表示します。通信切断などの結果不明時に自動再送しません。

API通信は1回だけ試みます。タイムアウトや5xxでは結果を確定せず、再送しません。認証・残高・入力・ポリシー関連の失敗も自動再試行しません。結果不明の条件を再実行すると追加課金される可能性があります。

## 保存したPNGをSD Extrasへ渡す

保存先の初期値はアプリ内の `output` フォルダーです。「設定」で任意の絶対パスに変更できます。保存名には日時とランダムIDを付けるため、元画像や以前の採用画像は上書きしません。

生成が完了すると自動保存します。保存先への書き込みに失敗しても、結果がアプリ内に残っていればPNGダウンロードで回収できます。API応答は `data/response_*.json` にも保持します。履歴の「記録」からマスクや応答データを取得できます。「原データ」は無変換のバイト列を `.bin` として取り出します。APIのPNG出力なら拡張子を `.png` にして開けます。

採用PNGをSD Extrasに手動で読み込み、SwinIRを選んで2倍に拡大してください。1920×1088の2倍は3840×2176です。現在はモード選択の「アップスケール」からアプリ内のSwinIRも利用できます。SDの実装が未指定のため、SDへの受け渡し操作自体は未検証です。

`data` には原画像、作業用PNG、資料、マスク、応答データ、SQLite履歴が入ります。バックアップはアプリを停止してから `data` と `output` を保存してください。この作業フォルダーはOneDrive配下なので、OS側の同期設定によっては画像・履歴も同期対象になります。外部への同期を避けたい場合は、アプリフォルダーごとOneDrive外へ配置してください。

## 困ったときに確認すること

| 状況 | 対処 |
| --- | --- |
| 起動時にポート使用中と表示 | 既に起動しているImage Atelierを確認。既存の別アプリは終了しない |
| APIキー設定が反映されない | 起動ターミナルを開き直して再起動 |
| 未対応寸法 | 1920×1088、2048×1152、1024×1024などに明示的に変更 |
| 保存先に書けない | フォルダーの権限・空き容量を確認し、PNGダウンロードで回収 |
| 結果不明 | 自動再実行せず、履歴・応答データ・公式Usageを確認 |
| 古い画面が表示される | サーバーを再起動し、ブラウザーを再読み込み |

解決しない場合は、このCodexタスクに操作手順とエラーの表示を伝えてください。APIキーは含めないでください。

## 用語と検証記録

モックは外部APIを呼ばない動作確認用の処理です。参照資料は編集の手掛かりとして送る画像、マスクは変更範囲を表す画像です。API生出力はサービスから受け取った画像、局所合成はアプリで元画像と組み合わせた結果を指します。

対応機能と残件は [進捗記録](docs/STATUS.md)、仕様確認は [実装メモ](docs/IMPLEMENTATION.md)、試験結果は [検証記録](docs/TEST_RESULTS.md)を参照してください。

最終更新: 2026-09-11

出力形式はPNG/JPEG/WebPから選べます。APIの原データはその形式のまま保持し、比較・合成・保存用にはPNGを作ります。複数枚ではそれぞれの結果を保持・保存します。既存の成功履歴も記録済みの概算額で精算します。結果不明の1回分は1 USDを保持します。

結果画像をクリックするか「大きく表示」を押すと、オーバーレイで表示します。ホイール・ボタンで拡大縮小、ドラッグで移動、100%で等倍、Escまたは「閉じる」で戻れます。この表示内の倍率・移動は比較画面に影響しません。

履歴の各サムネイル下の「次の編集対象にする」から、その画像を使った編集を始められます。履歴に保存された参照資料・変更指示・維持指示を引き継ぎ、ブラッシュアップ、実画像の寸法、1枚生成に設定します。古いマスクと結果表示はリセットし、送信指示文は改めて確認します。元の履歴と画像は残ります。

GitHubから取得した場合、APIキー設定ファイルは含まれません。`config.example.json` を `config.local.json` にコピーし、`openai_api_key` を設定してください。画像・履歴・出力・設計画像・個人用の実API試験スクリプトもアップロード対象外です。

## 登録確認・下書き・ローカル回収（2026-09-12更新）

実行ごとに新しいジョブを登録します。前の生成中に別条件を登録しても、並列数1で順に処理します。受付応答が分からない場合は「登録状況を確認（同じID）」を使います。送信時の指示文と画像の順序は固定して保持し、新しいIDで自動登録しません。

未送信の作業はブラウザーのIndexedDBへ自動保存します。画面上部で保存状態を確認でき、「下書きを保存」で保存を確定できます。手編集した送信指示文、参照資料、マスクと取り消し・やり直しも復元します。複数タブは別の下書きとして扱い、他の下書きや寸法調整前の状態は一覧からコピーとして読み込めます。別ブラウザーや別URLの保存領域は共有しません。

入力画像は「編集対象の寸法を調整」から、上部に指定した幅・高さへ調整できます。マスクがある場合は消去確認を行い、調整前の状態を保持します。加工結果は「ローカル編集の履歴」に保存され、無料で表示・ダウンロード・継続編集できます。

「ワーカー: 障害で一時停止」が出たら、空き容量・フォルダーの権限・設定を確認し、「ワーカーを再開」を押します。これは結果不明のジョブをAPIへ再送する操作ではありません。「保存応答を再処理」では手元に保存された応答から画像・合成・書き出しをやり直します。外部画像APIの呼び出しはありません。

移行前バックアップ、復元方法、今回の回帰テストと制約は [①〜③の修正記録](docs/FIXES_01_03.md) に記載しています。更新前から開いている画面は再読み込みしてください。旧版で保存していなかった未送信作業は回復できません。

## 異常時の補足（2026-09-12追補）

「保存失敗・未送信の登録」が表示された場合、登録情報を保存できるまで確認操作からも送信しません。保存環境が復旧したら「登録情報を保存して再確認」を使います。

画像取得が503や通信切断で失敗した場合は、下書きの画像IDを保持して自動保存を停止します。通信が復旧したら「下書き復元を再試行」を押してください。

書き出し先に不完全なPNGが残っている場合、「保存応答を再処理」で復旧できます。元ファイルは残し、必要に応じて `_recovered_` 付きの別名に保存します。正常な既存画像は上書きしません。

今回の取消競合・保存失敗・下書き復元・書き出し復旧の結果は [異常系修正記録](docs/ABNORMAL_CASE_FIXES.md) に記載しています。

## ローカルSwinIRで仕上げる

モードで「アップスケール」を選び、SwinIR・倍率・対象（元画像／生成後）を指定して共通の「アップスケール実行」ボタンを押します。結果は通常の「履歴・ジョブ」に表示されます。2倍が初期値で、1920×1088から3840×2176のPNGを作れます。指定解像度、小数倍率、透明余白・中央切り抜き・変形、タイル設定に対応しています。処理は専用子プロセスのGPUで行い、API料金や予約額には加算しません。

このPCは専用環境と提供モデルの設定済みです。別PCではsetup-swinir.ps1とローカルモデルが必要です。モデルやGPU環境が未設定でも既存API機能は使えます。[導入手順・対応上限・実GPU検証記録](docs/SWINIR.md) を参照してください。


### 変更・維持指示のプリセット

「変更すること」「維持すること」の「プリセットを選択」を開き、変更9種類・維持8種類から複数選択できます。表情・部位・衣装・質感・背景の角括弧部分は、選択後に入力欄で変更できます。「追加指示（手入力）」は定型文の後ろに加わります。「組み合わせた指示文」と実行前の「指示文を確認・編集」で内容を確認してください。

選択状態・可変欄・追加指示は下書きに保存します。既存の自由入力は追加指示として保持します。履歴の条件復元では、定型文として認識できる指示は選択状態へ戻し、それ以外は文章を保持します。キャラクター資料と維持指示の保存も引き続き利用できます。


履歴は「生成・編集」「アップスケール」「ローカル編集」の3タブに分かれ、各タブ20件ずつ表示します。上下の先頭・前へ・次へ・最後でページ移動できます。「設定フォルダーにPNG保存」はアプリ設定の出力フォルダーへ、「PNGダウンロード」はブラウザーのダウンロード先へ同じ画像を保存します。


## Dev-qwenのローカルモデル

モデル欄で「Qwen-Image-2.1（ローカル）」を選ぶと、新規生成・ブラッシュアップを専用GPU子プロセスで実行します。指示文とプリセット、結果操作、履歴は共用します。初期値は40ステップ・seed42・VAE512/stride384です。部分修正は初版では未対応です。導入と検証範囲は [Qwen開発版](docs/QWEN_TRIAL.md) を参照してください。
